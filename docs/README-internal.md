# 荣耀卡面工坊 (Card Personality)

给 **荣耀钱包（com.hihonor.wallet）** 卡片自定义卡面的 LSPosed 模块 + 配套编辑面板。

- 模块/面板包名：`com.cardpersonality.honor`（应用名：荣耀卡面工坊）
- 目标环境：荣耀 Magic 7 Pro（PTP-AN10），Android 17 / MagicOS 11.0.0.117，
  荣耀钱包 11.0.3.305（versionCode 1110003305）
- 依赖：KernelSU/Magisk 等 root + **LSPosed 2.2.1（API 102）**
- 构建：AGP 8.11.2 / Gradle 8.13 / JDK 17 / Kotlin 2.3.20 / Compose + Miuix 0.9.0

> 本模块**只做显示层替换**：不修改荣耀钱包的任何数据（数据库、卡片信息、NFC/SE 数据），
> 不上传任何内容，不改变支付/刷卡行为。禁用模块或清除配置后立即恢复原始卡面。

## 功能

1. **自定义卡面**：支持按“单张卡片”或“按卡片类型”为卡面换图，内置 336:208（13:21）等比裁切画布、
   12dp 圆角预览，所见即所得。
2. **面板编辑**：选图（相册 / 内置示例图）、拖动/双指缩放/双击复位、缩放与水平/垂直偏移滑杆、
   填充/适应/重置；支持叠加**文字贴纸**与**图片贴纸**（位置、大小、旋转、颜色）。
3. **元素组件**：荣耀钱包自身叠加在卡面上的界面元素（如公交卡详情页的站点状态标签、
   银行卡号、学生信息、门禁卡渐变层等）可在“组件”页选择 **保持原样（默认）/ 隐藏**；
   功能性元素（付款码、乘车码、定位按钮）不允许隐藏。
4. **实时生效**：面板保存后，钱包中的卡面在 1 秒内自动刷新（无需重启钱包）。
5. 支持卡片类型：交通卡、门禁卡、校园卡、银行卡、车钥匙、电动车钥匙（按 RE 结果逐类适配）。

## 安装

1. 安装 APK：`adb install -r 卡面工坊.apk`（或直接点击安装）。
2. 打开 **LSPosed 管理器** → 模块 → 启用「荣耀卡面工坊」。
3. 在「荣耀卡面工坊」的作用域中勾选 **荣耀钱包**（com.hihonor.wallet）。
4. 强行停止并重新打开荣耀钱包（模块在钱包进程启动时注入）。
5. 打开「荣耀卡面工坊」App，即可看到已识别的卡片列表。

## 使用

1. 在首页选择要自定义的卡片（已识别的单卡），或选择「按卡类型设置」为整类卡片设置默认卡面。
2. 进入编辑器：
   - **图片**：更换图片 / 使用示例图片，拖动与缩放调整构图（预览与钱包显示 1:1 同构）。
   - **元素**：添加文字/图片贴纸并摆放。
   - **组件**：选择荣耀钱包原卡片元素 保持原样 / 隐藏。
3. 点「保存」→ 切回荣耀钱包，卡面已更新。
4. 想恢复原卡面：编辑器里删除自定义（或在首页清除该卡片配置），保存即可。

## 安全与回滚

- 模块**不修改**荣耀钱包的数据目录、数据库、SE/NFC 数据；不发起网络请求；不读写支付相关接口。
- Hook 全部 fail-open：任何异常只会导致“不换卡面”，不会让钱包崩溃。
- 卸载/禁用模块：LSPosed 管理器中关闭「卡面工坊」→ 强行停止荣耀钱包 → 重新打开，即恢复原始卡面。
- 完全清理：卸载「卡面工坊」APK 即可（卡面配置与导出图保存在本 App 数据目录内）。
- 本模块开发/验证过程未对设备做任何系统级修改、未重启设备（bootloader 保持锁定）。

## 已知限制（v11-final 实测）

- 当前适配 **荣耀钱包 11.0.3.305**；钱包升级后混淆类名/方法可能变化，需要适配新版本。
- 卡包列表行已绑定的缩略图，切换配置后可能保持旧图，直到该行重新绑定（滚动/重进卡包/重启钱包）；详情页与大卡面实时刷新正常。
- 清空配置后版本号从 1 重新计数，极端情况下 content URI 复用可能短暂命中 Glide 缓存旧图（正常连续使用不会出现）。
- 刷卡页（SwipeCardStackView）可通过系统入口（如双击电源键快速刷卡）调起；adb 直接启动时界面停留在引导态、未绘制大卡面，
  故该面的视觉替换未在本次验收截图中确认（hook 路径已激活：nn0#p 记录、z79#d bind、H2 替换逻辑均已安装）。
- 元素组件仅支持“保持原样 / 隐藏”，不支持移动或重排；付款码、乘车码、定位按钮等功能元素禁止隐藏。
- 银行卡 / 校园卡 / 车钥匙 / 电动车钥匙的详情页适配已实现，但本机没有为这些卡配置过自定义卡面，故视觉验证仅覆盖
  交通卡（详情+列表）与门禁卡（列表+经典内置卡面路径）；车钥匙卡片保持原样（符合“未配置=不动”）。
- 门禁卡的“卡面样式”原生预览页有意排除，避免预览被覆盖。
- 卡面按 336:208（13:21）导出；钱包首页列表/刷卡页可见区域的 fitXY 比例差约 3.5%，属正常现象。
- “按卡类型设置”的编辑器不显示单一“当前卡面”底图（同一类型可能有多张卡）；单卡编辑器支持以当前卡面为底图。
- 桌面启动器可能短暂缓存旧应用名/图标，重启启动器或稍后自动刷新。

## 技术说明（简述）

- 钱包进程内通过 LSPosed 注入：在 `nh5#c`（Glide 卡面加载封装）等显示层 choke point 处，
  把“服务端卡面 URL”替换为本地 `content://com.cardpersonality.honor.face/card/<sha256>.jpg?v=N`；
  详情页适配器、列表绑定、门禁/电动车资源路径分别补充 hook；并处理预加载缓存（hv1/mv1）导致的旧图问题。
- 卡面 JPEG 由面板在保存时按 336:208 画布合成（1008×624），读取方（钱包）自有 Glide 负责解码与圆角裁剪。
- 配置与图片经只读 ContentProvider 跨进程提供；保存后通过广播 + ContentObserver 触发钱包内视图刷新。
- 全部 hook 代码包裹 try/catch 并失败降级；不触碰钱包数据模型，避免污染其数据库/网络语义。
